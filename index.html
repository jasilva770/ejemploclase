Domina Git & GitHub

Tu viaje hacia el control de versiones profesional comienza aquí.

1. Introducción a Git y GitHub

¡Bienvenido! Antes de escribir comandos, entendamos qué herramientas vamos a usar. Son dos cosas distintas pero que trabajan en equipo.

Git

Es un sistema de control de versiones. Se instala en tu computadora. Su trabajo es registrar los cambios en tus archivos para que puedas recordar qué hiciste en el futuro.

💡 Analogía: Es como el botón "Guardar" de un videojuego, pero para tu código.

GitHub

Es una plataforma en la nube donde se almacenan repositorios de Git. Te permite compartir tu código, colaborar con otros y tener un respaldo seguro.

💡 Analogía: Es como Google Drive o Dropbox, pero especializado en código.

Tu PC (Git Local)
La Nube (GitHub)

2. Instalación de Git

Necesitas instalar Git en tu sistema operativo. Ve a git-scm.com para descargar la última versión.

Windows

Descarga el instalador y sigue los pasos (usa las opciones por defecto).

git --version

Escribe esto en PowerShell para verificar.

macOS

Si tienes Xcode instalado, Git ya está. Si no, usa Homebrew:

brew install git

Linux

sudo apt update
sudo apt install git

3. Navegación por Terminal

Git se usa desde la línea de comandos. Conoce estos comandos esenciales para moverte por carpetas:

pwd Print Working Directory: ¿En qué carpeta estoy?
ls List: Muestra los archivos y carpetas actuales.
cd nombre_carpeta Change Directory: Entrar a una carpeta.
mkdir nombre Make Directory: Crear una nueva carpeta.
touch archivo.txt Crear un archivo vacío.
rm archivo.txt Remove: Borrar un archivo (¡Cuidado!).

4. Configuración Inicial

La primera vez que instalas Git, debes decirle quién eres. Esto se guarda en todos tus commits.

git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"

Puedes verificar la configuración con:

git config --list

💡 Tip Pedagógico

Usa el email asociado a tu cuenta de GitHub para que tus contribuciones se vinculen correctamente en tu perfil.

5. Inicializar un Repositorio

Para empezar a usar Git en un proyecto, debes "inicializarlo". Esto crea una carpeta oculta .git que contiene todo el historial.

mkdir mi-proyecto
cd mi-proyecto
git init

Salida esperada: Initialized empty Git repository in ...

6. El Ciclo de Commits

Git tiene tres áreas principales. Entender este flujo es la clave de todo:

Directorio de Trabajo
(Tus archivos)
git add
📦 Staging Area
(Preparado)
git commit
💾 Repositorio
(Historial)

1. Ver el estado

git status

Te dice qué archivos han cambiado y en qué área están.

2. Agregar al Staging

git add archivo.txt   # Un archivo
git add .             # Todos los cambios

3. Guardar el cambio (Commit)

git commit -m "Agregué el archivo de inicio"

📝 Buenas prácticas para mensajes:

  • Usa el modo imperativo ("Agregar", no "Agregado").
  • Sé específico pero breve.
  • Explica el "qué" y "por qué", no el "cómo".

7. Historial y Diferencias

¿Qué ha pasado en el proyecto? ¿Qué cambié en un archivo?

Ver historial de commits

git log                # Historial completo
git log --oneline      # Una línea por commit (muy útil)

Ver diferencias

Antes de hacer commit, puedes ver qué líneas cambiaron:

git diff               # Cambios no preparados
git diff --staged      # Cambios listos para commit

8. Restablecer Cambios

Todos cometemos errores. Git tiene varias formas de deshacer cosas.

Descartar cambios en un archivo

Si modificaste un archivo y quieres volver a como estaba en el último commit:

git restore archivo.txt

Sacar un archivo del Staging

Hiciste git add pero no quieres commitearlo aún:

git restore --staged archivo.txt

Deshacer commits (Reset)

⚠️ Zona Peligrosa

Reset reescribe la historia. Úsalo con cuidado si ya subiste los cambios a GitHub.

git reset --soft HEAD~1   # Deshace el commit, mantiene cambios en staging
git reset --mixed HEAD~1  # Deshace commit y staging (default)
git reset --hard HEAD~1   # DESTRUYE todo: commit, staging y cambios locales

Revertir un commit seguro

Crea un nuevo commit que deshace los cambios de uno anterior. Seguro para historia compartida.

git revert HASH_DEL_COMMIT

9. Trabajo con Ramas

Las ramas te permiten trabajar en nuevas funciones sin afectar el código principal. Es como hacer una copia paralela del proyecto.

main ──●────●────●
               ↘
feature       ●────●───

Crear y cambiar de rama

git branch nueva-rama       # Crear rama
git checkout nueva-rama     # Cambiar a rama (tradicional)
git switch nueva-rama       # Cambiar a rama (moderno)

Unir ramas (Merge)

Vuelve a la rama principal y fusiona los cambios:

git checkout main
git merge nueva-rama

Resolución de conflictos

Si Git no puede mezclar cambios automáticamente, verás un conflicto. Debes editar el archivo manualmente, quitar los marcadores <<<<<<<, guardar y commitear.

10. Conectar con GitHub

Tu repositorio local necesita saber dónde está su "gemelo" en la nube.

1. Crear repo en GitHub

Ve a github.com/new y crea un repositorio vacío. Copia la URL (ej: https://github.com/usuario/repo.git).

2. Conectar remoto

git remote add origin https://github.com/usuario/repo.git

3. Subir cambios (Push)

La primera vez necesitas vincular la rama:

git push -u origin main

Luego solo usarás git push.

11. Sincronización

Mantén tu repositorio local y remoto al día.

git push

Sube tus commits locales a GitHub. Envía tu trabajo al mundo.

git pull

Descarga cambios de GitHub y los fusiona en tu rama actual. Úsalo antes de empezar a trabajar para tener la última versión.

12. Conceptos Adicionales

.gitignore

Archivo que le dice a Git qué archivos NO rastrear (ej: carpetas node_modules, archivos de configuración local, imágenes pesadas).

# Ejemplo de .gitignore
node_modules/
.env
*.log

git clone

Descarga un repositorio completo desde GitHub a tu PC.

git clone https://github.com/usuario/proyecto.git

fetch vs pull

git fetch solo descarga la información de cambios remotos sin mezclarla con tu trabajo. git pull hace fetch + merge automáticamente.
